## 3. How They Interact

| Direction | What flows | Mechanism |
|-----------|------------|-----------|
| **User → UI** | Input text, slash commands (`/model`, `/clear`) | React components call `store.setState(...)`; Textual widgets emit events (`ChatInput.Submitted`). |
| **UI → Backend** | API calls to `/api/...` | React uses `fetch` (or a wrapper) in the components; Textual uses `httpx.AsyncClient()` inside async workers. |
| **Backend → UI** | Streaming SSE (`/api/stream/{session_id}`) | Textual uses `client.stream` to receive lines; React would use `EventSource` (planned). |
| **State Sharing** | Both UIs maintain their own local state but share the same API contract. The Zustand store holds global data for the web UI; Textual keeps state in reactive properties (`reactive` fields). |
| **Model Selection** | `/model <name>` command updates `current_model`. The backend uses this value to choose the AI SDK. |
| **Session Flow** | User submits a prompt → UI posts `/api/execute` → backend returns `session_id`. UI then streams from `/api/stream/{session_id}` until a `done` event is received. |
