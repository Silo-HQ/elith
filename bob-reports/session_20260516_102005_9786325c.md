## 3. How They Interact

### Frontend ↔ Backend
1. **Scan Repo** – UI calls `POST /api/scan` with `repo_path` and `vault_path`. Backend returns repo metadata.
2. **Execute** – UI posts to `/api/execute` with `{model, operation, repo_path, prompt}`. Backend creates a `session_id`.
3. **Stream** – UI (or TUI) opens an SSE stream on `/api/stream/{session_id}`. Each event contains `{type, content, model}`.
4. **Proposals / Results** – After execution completes, UI fetches `/api/proposals/{session_id}` and `/api/results/{session_id}`.

### TUI ↔ Backend
The `ElithApp` in `tui/app.py` does the same steps as the web UI:
* `check_backend()` → `/api/models`
* `process_message()` → `/api/execute`
* `stream_response()` → `/api/stream/{session_id}`
* Commands (`/model`, `/repo`, etc.) modify internal state and update widgets.

### State Flow
* **Frontend**: Store updates trigger re‑renders of components that subscribe to the relevant slice.
* **TUI**: Reactive attributes (`reactive`) on widgets (e.g., `StatusBar.active_model`) automatically update the UI when changed.
