# Elith – A Unified AI‑Driven IDE

Elith is a full stack project that lets you run AI operations on your code base from either a **web dashboard** or a **terminal UI**.  
The repository contains three main parts:

| Layer | Directory | What it does |
|-------|-----------|--------------|
| **Frontend** | `frontend/` | React + TypeScript web UI (Vite, Tailwind). |
| **Backend**  | `backend/` | FastAPI server that talks to the AI SDKs and streams results. |
| **TUI**      | `tui/`     | Ink‑based terminal UI written in TypeScript that re‑uses the same API client and types as the web app. |

Below is a walk‑through of how all these pieces fit together.

## 3. How They Interact

1. **User → Frontend/TUI**  
   * In the web UI, a user types an operation in `BottomBar` or clicks a button.  
   * In the TUI, the user types a prompt or slash command in `ChatInput`.

2. **Component → Store / API**  
   * Web components dispatch actions to the Zustand store (`elithStore.ts`).  
   * The store contains helper methods that call the API client (`api.execute`, `api.streamSession`, etc.).

3. **Store → Backend**  
   * The store’s async actions use the shared `api.ts` to POST `/execute`.  
   * It receives a session ID, stores it in state and opens an SSE connection to `/stream/{session_id}`.  
   * Live output events are appended to `liveOutput` in the store, which triggers re‑rendering of `LiveOutput.tsx`.

4. **Backend → UI**  
   * The backend streams incremental responses via SSE.  
   * The web front‑end uses the `EventSource` API (not shown in the snippet but planned) to listen and update state.  
   * The TUI uses the `eventsource` npm package inside `src/services/api.ts` to consume the same stream.

5. **Results / Proposals**  
   * After a session finishes, `api.getResults(session_id)` or `/proposals/{session_id}` is called.  
   * The returned data populates the `results` or `proposals` slice of the store, which is rendered by `Results.tsx` or `Proposals.tsx`.

6. **Shared Types**  
   * Both UI layers import the same TypeScript interfaces from `src/types/api.ts`.  
   * If a new API field is added, only that file needs to be updated and both UIs compile against it.

## 5. Entry Points

| Platform | File / Command | What it does |
|----------|----------------|--------------|
| **Backend** | `python -m uvicorn backend.main:app --reload` | Starts FastAPI on port 8000. |
| **Web Frontend** | `npm run dev` in `frontend/` | Vite dev server on port 3000, proxies `/api/*` to the backend. |
| **Terminal UI** | `npm run dev` or `elith-tui` in `tui/` | Starts the Ink app; `./dist/index.js` is installed as a global CLI via npm link. |

*When you run the web dev server, it automatically forwards API calls to `http://localhost:8000/api` thanks to the proxy setting in `frontend/vite.config.ts`.  
The TUI, on the other hand, uses a hard‑coded `API_BASE` URL (`http://localhost:8000/api`) inside `tui/src/services/api.ts`.*

### Quick Getting Started

1. **Install dependencies**  
   ```bash
   # Root – backend Python deps
   pip install -r requirements.txt

   # Frontend
   cd frontend && npm install

   # TUI
   cd tui && npm install
   ```

2. **Run the backend**  
   ```bash
   python -m uvicorn backend.main:app --reload
   ```

3. **Run the web UI**  
   ```bash
   cd frontend && npm run dev
   ```

4. **Run the terminal UI**  
   ```bash
   cd tui && npm run dev  # or `npm link` then `elith-tui`
   ```

5. **Explore the code**  
   * Open `frontend/src/components/` to see how UI widgets are built.  
   * Look at `tui/src/services/api.ts` to see the shared API layer.  
   * The backend routes live in `backend/` (look for `router.py` or similar files).

## Take‑away

* Elith is a **dual‑interface** project – the same backend, same API contracts, two front ends (web + terminal).  
* The **shared TypeScript types** and API client guarantee consistency across UI layers.  
* State is held in a single **Zustand store** on the web side, while the TUI keeps state locally inside React hooks.  
* The architecture is intentionally modular: adding a new component or page only touches the UI side; the backend stays untouched until you need a new endpoint.  

With this overview, you should be able to jump into any of the three layers, understand how data flows, and start contributing new features or bug fixes. Happy coding!
