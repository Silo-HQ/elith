## 3. How They Interact

1. **State Flow (Web UI)**  
   * The `elithStore` holds all shared data. Components read from the store via `useStore()` and update it with actions (e.g., `setRepoPath`).  
   * When the UI needs to start a new operation, it would (in future) call an API endpoint (`/api/execute`) and then update `sessionStatus` in the store.

2. **API Interaction**  
   * Both UIs are designed to call the same backend API once it is implemented.  
   * The web UI will use `fetch`/`axios` (not yet in code) to POST `/api/scan`, `/api/execute`, GET `/api/stream/{id}`, etc.  
   * The TUI will use async HTTP requests (e.g., `httpx`) to perform the same calls and process SSE streams.

3. **Terminal UI Flow**  
   * `ElithApp` starts with `WelcomeScreen`.  
   * User actions (e.g., pressing Enter) trigger navigation to other screens via `self.app.push_screen(...)`.  
   * Each screen uses its own components (`InputBar`, `OutputPanel`) to render data.  
   * Future implementation will inject a shared state or event bus so screens can react to SSE updates.

4. **Mock Data**  
   * Until the backend is ready, both UIs read from `mockData.ts` (web) or hard‑coded dictionaries in the TUI components.  
   * This allows UI development to proceed independently of the backend.
