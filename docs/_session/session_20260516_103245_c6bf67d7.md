The repository is split into **two UI layers** that talk to the same backend:

| Layer | Purpose | Key files |
|-------|---------|-----------|

Both UIs share the same API (`http://localhost:8000/api/...`) and use the same data contracts (JSON). The backend is responsible for:

* Scanning a repo (`POST /api/scan`)

* Returning proposals and final results

The front‑end and TUI only **consume** these endpoints; they do not contain any business logic.

## 3. How They Interact

1. **User Interaction**  
   *Web*: User types a prompt in the input box → submits → triggers an API call.  
   *TUI*: User types in `ChatInput` → submits via `/` or `Enter` → triggers an API call.

2. **API Call**  
   *Both UIs use `httpx` (TUI) or fetch/axios (not shown in the snippet, but would be used in React). They POST to `/api/execute` with:
   ```json
   {
     "model": "<current model>",
     "operation": "explain",
     "repo_path": "...",
     "prompt": "<user text>"
   }
   ```  
   The backend returns a `session_id`.

3. **Streaming**  
   After receiving the session ID, the UI starts listening to `/api/stream/{session_id}`.  
   *TUI*: `app.py`’s `stream_response()` reads SSE lines, collects content, and appends a single message when the `"done"` event arrives.  
   *Web*: A similar component (not yet implemented) would use `EventSource` to stream data and update the UI in real time.

4. **State Management**  
   *Web*: The Zustand store (`elithStore.ts`) holds the current session ID, model selection, live output array, etc. Components read/write via `useStore`.  
   *TUI*: The `StatusBar` and other widgets are reactive; they update automatically when their properties change.

5. **Commands**  
   Both UIs support slash commands (`/help`, `/models`, `/model …`, `/clear`, `/repo …`). The TUI parses commands in `handle_command()`; the web UI would do the same via a command handler component.

6. **Navigation**  
   The TUI uses Textual screens (`welcome`, `workspace`, etc.) to move between stages. The web UI uses React Router routes.

### Quick Take‑away for a New Developer

1. **Choose the UI you want to work on** – web or terminal.
2. **Start the backend first** (`uvicorn backend.main:app`).  
3. For web, run `npm install && npm run dev`.  
4. For TUI, run `pip install -r requirements.txt` then `python tui/app.py`.  
5. Look at the **Zustand store** (`elithStore.ts`) or the Textual `StatusBar` to see how state flows.  
6. When you need real data, replace mock calls in the UI with the actual `httpx`/fetch requests as shown in `app.py`.  
7. Keep an eye on the **API routes** (`/api/...`) – they are the bridge between UI and backend.
