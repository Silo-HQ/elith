## 3. How They Interact

1. **User → UI**  
   *Web* – user types in the `BottomBar` (or clicks a card).  
   *TUI* – user types in the `ChatInput` or presses a key binding.

2. **UI → Backend**  
   Both UIs make HTTP calls to `http://localhost:8000/api/...`.  
   *Frontend* uses `fetch` (or axios if added) – see the placeholder in `src/pages/Workspace.tsx`.  
   *TUI* uses `httpx.AsyncClient` – see the helper methods in `app.py` (`check_backend`, `process_message`, `stream_response`).

3. **Backend → UI**  
   *Streaming* – the `/api/stream/{id}` endpoint pushes SSE events.  
   *Frontend* would consume them via `EventSource` (planned).  
   *TUI* uses `client.stream(...)` and parses each line, updating the `MessagesPanel`.

4. **State Sync**  
   *Frontend* keeps a global Zustand store; the UI components subscribe to that store.  
   *TUI* uses Textual’s reactive attributes (`@reactive`) to auto‑update widgets when state changes.

5. **Command Parsing**  
   Both UIs support slash commands (`/help`, `/models`, `/model …`).  
   The TUI’s `handle_command` method lives in `app.py`; the frontend would have a similar handler in its chat component.

> **Getting started**  
> 1. **Backend** – `pip install -r requirements.txt` then run the FastAPI server (you’ll need a `backend/main.py` that implements the API).  
> 2. **Frontend** – `cd frontend && npm install && npm run dev`. Open `http://localhost:3000`.  
> 3. **TUI** – `cd tui && pip install -r requirements.txt && python app.py`.  
> 4. **API** – both UIs will hit `http://localhost:8000/api/...`. If the backend isn’t running you’ll see “⚠ Backend not available” in the TUI and a 404 on the web console.
