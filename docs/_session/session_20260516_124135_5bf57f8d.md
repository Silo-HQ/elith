## 3. How They Interact

1. **Backend ↔ Front‑ends**  
   *All three UIs* call the same FastAPI endpoints.  The contract is defined in `frontend/src/types/api.ts`.  
   Example: the web dashboard calls `/api/execute` via `services/api.execute()`, and the TypeScript TUI does the same through its `api.execute()`.

2. **Shared Code**  
   *API types* and *client implementation* are copied from `frontend` to `tui-ts`.  This eliminates duplication and keeps the terminal UI in sync with the web UI.

3. **State Flow**  
   *Web* uses Zustand to keep global state; actions (e.g. `scan`, `execute`) dispatch async thunks that update the store, which in turn re‑renders components.  
   *Python TUI* holds state inside the `Screen` instances (e.g., a list of messages, session id).  Screens subscribe to the Textual event system (`self.app.push_screen(...)`) and update widgets via methods like `add_output`.

4. **Command Handling**  
   *TypeScript TUI* parses input starting with `/` in `App.tsx`.  Commands such as `/model`, `/clear` trigger API calls or UI updates.  
   *Python TUI* handles key bindings in each screen (`BINDINGS`) and reacts to `Enter` or slash commands inside the `InputBar`.

5. **Streaming**  
   When a command is executed, both UIs open an SSE stream (`api.streamSession()` or `eventsource`).  The Python UI uses Textual’s async event loop to consume events; the TypeScript UI uses `eventsource` and updates the `MessagesPanel`.

6. **Navigation**  
   *Web* uses React Router (`<Routes>`) to switch pages.  
   *Python TUI* pushes/pops screens (`self.app.push_screen`, `self.app.pop_screen`).  
   *TypeScript TUI* is a single‑screen app; navigation is handled by showing/hiding components based on state.

### What Happens on Startup?

1. **Python TUI**  
   - `app.py` creates a `ElithApp(Textual)` instance.  
   - Registers all screens (`WelcomeScreen`, `WorkspaceScreen`, …).  
   - Calls `run()` to start the event loop.

2. **TypeScript TUI**  
   - `index.tsx` renders `<App />` inside Ink’s `render`.  
   - `<App />` sets up state (repo path, current model) and renders `StatusBar`, `ChatInput`, and `MessagesPanel`.  
   - Listens for key events; when `/` is typed, it parses the command and calls the API.

3. **Web**  
   - `main.tsx` mounts `<App />` into the DOM.  
   - `<App />` sets up React Router and Zustand store.  
   - Pages fetch data lazily (e.g., `useEffect` calling `api.scan()` on the landing page).
