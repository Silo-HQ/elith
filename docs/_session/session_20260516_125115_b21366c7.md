## 3. How They Interact

| Interaction | Where it happens | What flows |
|-------------|-----------------|------------|
| **User → UI** | Keyboard in the terminal or mouse/keyboard in the browser. | Commands, form submissions, navigation. |
| **UI → Backend** | `api.ts` (both TS and Python) sends HTTP requests to `http://localhost:8000/api`. | `/scan`, `/execute` → returns session IDs. |
| **Backend → UI (stream)** | SSE endpoint `/stream/{session_id}`. | Real‑time AI output lines, progress updates. |
| **UI → UI (shared state)** | `zustand` store in frontend; React `useState`/`useEffect` in TS TUI. | Live output, session status, model list are kept in sync. |
| **Backend → UI (results)** | `/results/{session_id}` endpoint. | Final session summary, file diffs, etc. |
| **UI → UI (commands)** | Slash commands in TS TUI (`/model`, `/repo`). | Trigger API calls or change local state. |

The **Python TUI** and the **TypeScript TUI** are independent front‑ends; they share *only* the backend API. The **frontend** (web) and **TS TUI** share *code* – the same `api.ts` and type definitions (`src/types/api.ts`). This guarantees that any change to the contract needs only be made once.

|----|------|---------------|
| **Python TUI** | `tui/app.py` | Running `python tui/app.py` (or `python -m tui.app`) starts the Textual event loop and shows the Welcome screen. |
| **TypeScript TUI** | `tui-ts/src/index.tsx` | Executed by `tsx src/index.tsx` (via the `dev` script). Ink renders `<App />` to the terminal. |

## Quick‑Start Checklist

1. **Backend**  
   ```bash
   pip install -r requirements.txt
   uvicorn backend.main:app --reload --port 8000
   ```
2. **Python TUI** (legacy)  
   ```bash
   python tui/app.py
   ```
3. **TS TUI** (recommended)  
   ```bash
   cd tui-ts
   npm install
   npm run dev   # or ./run.sh
   ```
4. **Web Front‑end**  
   ```bash
   cd frontend
   npm install
   npm run dev   # opens http://localhost:3000
   ```
