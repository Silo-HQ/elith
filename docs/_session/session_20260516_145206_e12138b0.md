The code lives entirely in the `src/` folder. The `components/` directory contains pure UI pieces that are completely stateless except for the props they receive. All state lives in `App.tsx` and is passed down via React context / props.

The **services/api.ts** file is the single source of truth for talking to the backend (`http://localhost:8000/api`). It uses `node-fetch` for HTTP requests and the `eventsource` package to consume Server‑Sent Events (SSE) streams.

The **types/api.ts** file is deliberately shared with the web frontend; it defines all request/response shapes used by both projects.

### How They Work Together

1. **User Input** – The user types into `ChatInput`. When they hit *Enter*, the input string is passed to a handler in `App.tsx`.
2. **Command Parsing** – `App` checks if the string starts with `/`. If so, it matches against known commands (`/help`, `/models`, `/model <name>`, etc.) and calls the appropriate API service.  
   - For `/model <name>` it updates state (`currentModel`) and clears the chat.  
   - For `/repo <path>` it changes the repo context.
3. **Normal Messages** – If the input is not a command, `App` sends it to `api.execute()` which POSTs to the backend.  
   - The backend replies with an SSE stream (`api.streamSession()`). `App` subscribes to that stream and appends incremental chunks to the message list as they arrive.
4. **State Updates** – All new messages, model changes, and repo paths are stored in `App`’s state.  
   - `MessagesPanel` receives the message array as a prop and renders each item, using `cli-highlight` for code blocks.  
   - `StatusBar` shows the current model and repo path.
5. **Error Handling** – If any API call fails, `App` pushes an error message into the chat (type “system”) so the user sees it immediately.
