## 3. How They Interact

1. **Bootstrapping**  
   `src/index.tsx` mounts `<App />`. Ink creates the terminal UI.

2. **User Input**  
   `ChatInput` captures a line of text and calls its `onSubmit` prop.  
   In `App`, the handler checks if the line starts with `/`. If so, it runs a command (e.g. `/model`, `/clear`). Otherwise, it treats the line as a normal chat message.

3. **Command Handling**  
   Commands are defined in `src/types/commands.ts`. The handler in `App` calls the appropriate API method (e.g. `api.getModels()` or `api.scan()`) and updates state accordingly.

4. **API Interaction**  
   `App` uses the functions exported from `api.ts`. For long‑running actions (like a model response), it calls `streamSession()` which returns an EventSource. As events arrive, the handler updates a “thinking” flag and appends partial messages to the message list.

5. **Rendering**  
   - `MessagesPanel` shows all chat messages stored in `App.state.messages`.  
   - When a “thinking” flag is true, `ThinkingPanel` appears.  
   - The status bar (`EnhancedStatusBar`) reads the current model, repo path, and any task state from `App`’s state.  
   - Screens like `Welcome` are rendered conditionally (e.g., before a repo path is set).

6. **State Flow**  
   All state lives in `App`. It passes callbacks and data down to components via props. Components are stateless (or very light‑weight) – they just render based on the data they receive.
